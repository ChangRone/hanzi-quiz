# E｜真實手寫辨識驗收協定（2026-10-15）

## 狀態與事實邊界

- 正式網站上線：**NO**；PR #6 持續 Draft、功能預設關閉。
- 現有 GitHub CI 驗證的是 **程式行為、位置、點擊、資料紀錄與報告邏輯**，不能取代真人手寫準確度。
- 本次 Repo 與附件中未找到可用的實際真人筆跡集／人工驗證結果；驗收狀態必須保持 `INSUFFICIENT_EVIDENCE`。
- 版型固定：`config/zhuyin-compact-layout-v2.json`，聲調在中格右側（這是操作格，不是教育部印刷聲調標注位置）。

## 一、真人採樣（必要）

使用 `poc/zhuyin-handwriting-qa/index.html`，下載 Raw HTML，直接在平板或觸控式電腦的瀏覽器開啟，**不用打開正式 Quiz**。

每筆資料先寫完，再由人確認實際寫出的是：

- `correct`：符號與所在練習格都正確
- `position`：符號正確，但刻意／實際寫錯格
- `incorrect`：符號錯、漏寫或多寫

人工判定不能只看系統結果倒推。每筆都選真實輸入方式：`finger`、`stylus` 或 `mouse`；滑鼠不當作真人觸控證據。範例顯示讀音是用於測**筆跡辨識**，不是用於測默寫記憶。

### 初步建議採樣矩陣（專案自行制定，不是教育部合格門檻）

| 類別 | 最低樣本數 |
|---|---:|
| 符號與位置都正確 | 9 種讀音 × 3 = **27** |
| 符號錯誤／漏寫／多寫 | 9 種讀音 × 3 = **27** |
| 符號正確但位置錯 | 9 種讀音 × 1 = **9** |
| 輕聲單次點擊 | 另外至少 **3** 次（可以包含在前述正確樣本） |

合計至少 **63 筆**。範圍內必須包含：`ㄇㄠ`、`ㄒㄧㄤˋ`、`ㄧ`、`ㄕㄨˊ`、`ㄕㄨ˙`、`ㄩˇ`、`ㄩㄢˊ`、`ㄒㄩˊ`、`ㄒㄩㄢˊ`。

## 二、採樣紀錄／隱私

- HTML 離線使用；**不傳送資料到第三方**，不存進 Quiz IndexedDB。
- 每次點「檢查注音」，人工分類和系統結果一同記入當頁的記憶體。
- 預設只匯出 **匿名結果摘要**：讀音、人工標註、系統判定、筆跡是否可辨、輸入方式，無姓名與原始筆畫。
- 如果確實要分析個別符號的誤判，可以主動勾選「另外匯出原始筆跡座標」；這是可選的本機 JSON，**必須由使用者自行決定是否提供**。不要把學生原始筆畫提交 GitHub Repo。
- 關閉或重新整理頁面會失去未匯出紀錄，所以每次測完應匯出 JSON。

## 三、統計與初步 Gate（暫定標準）

`assets/zhuyin-real-handwriting-qa.js` 會計算：人工三類 × 系統四類之混淆矩陣、真人觸控樣本數、9 種讀音覆蓋、輕聲單點偵測、誤判為完全正確的比例。

只有充足**真實觸控**資料才考慮 `ACCEPTED_ON_SUBMITTED_SAMPLES`：
- 事先符合全部採樣數量、9 種讀音覆蓋；
- 正確寫法判 PASS ≥ 90%；
- 錯誤符號判完全 PASS = 0 次；
- 位置錯的判完全 PASS = 0 次；
- 位置錯的判 `position_only` ≥ 70%；
- 已記錄的輕聲單點檢出率 100%。

未達數量標 `INSUFFICIENT_EVIDENCE`；足量但達不到上述品質標 `NOT_ACCEPTED`。測完一個人的樣本不代表不同學生、不同書寫工具也同樣有效；學校導入前仍須再抽測真實班級與其他裝置。

## 四、交付與後續

提交或傳回 **匿名 QA JSON** 即可進一步分析。如辨識有大量 `UNCERTAIN`，要先從已獲同意的錯誤筆跡找出原因，再修改範本、容錯或模型，不能只降低門檻讓不相干符號更容易判 PASS。

在取得真實樣本與統計之前：**不得自稱 E 的真人手寫準確度驗收完成，也不得解除 PR Draft 或正式部署。**
